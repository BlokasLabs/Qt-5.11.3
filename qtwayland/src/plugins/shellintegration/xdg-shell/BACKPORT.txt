Stable xdg-shell client backport
===============================

Dock dragging and tool-window grouping:
- QDockWidget uses a platform drag on compositors advertising
  xdg-toplevel-drag-v1. The compositor moves the actual floating surface while
  QMainWindow receives drag-enter/move/leave/drop events in its own coordinates.
  This applies both to a panel being undocked and to an already floating panel.
  The original surface stays mapped when starting a drag from a floating panel.
- The platform-drag flow follows upstream Qt's QDockWidget/QMainWindowLayout
  design. The window reference is passed as an in-process QDrag property, not
  a pointer serialized into MIME data.
- The four core data-device protocol interfaces are updated to version 3
  (definitions from Wayland 1.23.1). Drop-performed, finished, and cancelled
  events distinguish a drop outside the main window from Escape cancellation.
- xdg-toplevel-drag-v1.xml is from wayland-protocols, staging/xdg-toplevel-drag.
  plasma-shell.xml is from KDE plasma-wayland-protocols, src/protocols. Their
  upstream copyright/license notices are retained in the XML files.
- On KWin, transient Qt::Tool windows request skip-taskbar and skip-switcher
  through org_kde_plasma_surface. The main window keeps its normal switcher
  entry. This optional metadata does not change the xdg_toplevel parent.
- Compositors/shell integrations without toplevel-drag support retain the
  compositor-move fallback: use the re-dock button or title-bar double-click.

Regression checks: tst_qdockwidget platformDockDrag covers docked/floating
drags into a different dock area and cancellation in either starting state.
waylandBorderResize covers all eight resize handles. Run these at scale 1 and
with QT_SCALE_FACTOR=2. A real compositor is also required to check that the
panel tracks the pointer during the initial undock, remains at the release
position, and can be re-docked by a subsequent drag. Validate KWin's
skipSwitcher/skipTaskbar flags for the floating panel, not just the protocol
requests. The main window must remain switchable.

Window icons: the plugin also implements xdg-toplevel-icon-v1 using the
vendored XML from wayland-protocols. When the compositor advertises this
optional protocol, initial and updated QWindow icons are sent as shared-memory
pixel buffers, including the output scale. Null icons clear the override.
No desktop entries or icon files are installed. Compositors without the
protocol retain their normal desktop-entry/default icon behavior.

Source: qt/qtwayland tag v5.12.12, src/plugins/shellintegration/xdg-shell,
with xdg-shell.xml and xdg-decoration-unstable-v1.xml from the same tag.
The upstream copyright and license notices are preserved.

Adaptations for Qt 5.11.3:
- Role creation uses setType(), followed by an initial bufferless commit.
- Configure events use the existing queued QWaylandWindow::configure() resize
  path instead of the Qt 5.12 applyConfigureWhenPossible() API.
- Window-state requests use the Qt 5.11 shell surface hooks. Compositor state
  reports update the window without sending state requests back.
- Server-side decoration negotiation uses a backported wantsDecorations() hook.
- Registry listeners are removed when the shell integration is destroyed.
- QWaylandScreen uses Qt 5.12's 96 logical DPI baseline. Desktop scaling is
  supplied by the Wayland output device pixel ratio. QT_WAYLAND_FORCE_DPI can
  override the baseline, or select "physical" to restore the old calculation.
- Plugin classes have Stable suffixes and are not exported by QtWaylandClient.
- The stable XML file and its protocol group name are suffixed with "stable"
  so Qt 5.11's scanner produces matching filenames. Wire interface names,
  including xdg_wm_base, are unchanged.
- Obsolete xdg-shell v5 client sources/protocol are excluded from the build:
  their xdg_surface/xdg_popup names conflict with the stable protocol.
  xdg-shell-v6 and wl-shell remain available as fallbacks.
- Automatic shell selection tries stable xdg-shell first, and continues to
  the next candidate if an integration cannot initialize.

Rebuild and install the QtWayland client library AND all its client plugins.
The shell-surface private vtable changed; do not mix old Wayland plugins with
the rebuilt library. This backport adds client support only.

After installation, plugins/wayland-shell-integration/libxdg-shell.so should
exist. Launch Midihub Editor in a Wayland desktop session with:

  QT_QPA_PLATFORM=wayland QT_WAYLAND_SHELL_INTEGRATION=xdg-shell \
    QT_DEBUG_PLUGINS=1 ./midihub-editor

Expected log: Using the 'xdg-shell' shell integration.
Test showing/hiding windows, resizing, maximizing/restoring, fullscreen,
minimizing/restoring, dialogs, context menus, nested menus, and tooltips.
Then test pipe dragging within the editor, outside its window and back in,
and between two editor processes. Confirm accepted/rejected cursors and that
releasing or cancelling a drag always ends the operation.

Repeat without QT_WAYLAND_SHELL_INTEGRATION to test automatic selection.
Launch with QT_QPA_PLATFORM=xcb to check that the X11 path still works.
Runtime behavior on KWin remains a separate check from compilation.

The Blokas Linux configure scripts disable IVI shell and custom Qt compositor
server buffer integrations through -no-feature-wayland-ivi-shell and
-no-feature-wayland-server-buffer. Standard QtWayland builds retain these
features by default. Disabled plugins are omitted from build/install targets.
